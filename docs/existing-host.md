# 与已有代理共存

面板支持 sing-box 与 Xray 在同一服务器共存，也支持只安装其中一种监控来源。默认保留旧 sing-box 行为；`xray.instances` 非空时主界面默认 Xray；仅 Xray 时设 `singbox.enabled=false`。详细配置见 [Xray 接入](xray.md)。

## 接入原则

1. 只读确认实际服务、完整配置、已有 API、Nginx 主配置和监听端口，再备份实际文件与账本。不要凭目录名称猜测服务归属。
2. 各核心 API 使用不同回环端口，面板不接管节点认证、上游、路由、TLS 网站或其他管理工具的 metadata。
3. Xray 原生统计需 StatsService。可通过独立 `-config` 叠加文件启用，先对完整实际命令做配置测试；首次启用需重启对应核心，会短暂断开连接。已有 API 时整合现有设置，不能盲目叠加第二个 API。
4. 面板用自己的目录和 systemd 单元，HTTPS 只添加明确的子路径反代。Nginx 检查/reload 必须使用实际运行的主配置与服务，不能假设系统默认配置。
5. 后续升级先运行隔离测试，备份 release、settings、systemd 单元及 SQLite（使用 SQLite backup API），再切换面板版本；只重启面板，核对核心 PID、配置哈希、实际端到端链路和账本增量。
6. SSH 断连不代表变更未提交。先只读确认 release、备份/提交记录、监听和健康状态，再决定恢复；禁止盲目重放安装或覆盖原配置。

## 两种权限范围

- sing-box 版本保留原有连接关闭、iptables/ip6tables 受限入口和经验证 CDN 网关。它的封禁不覆盖 Xray。停用前需检查残留规则和已有网关依赖，不自动删除其他服务规则。
- Xray 版本当前只读统计。独立单元示例不授予网络管理权限，也不需要 `/run/xtables.lock`。将已有 sing-box 面板切为独立 Xray 时，先由实际运维流程处理旧封禁/CDN 网关依赖，再停用相关功能。
- sing-box 面板单元保留 tmpfiles 初始化与 `ReadWritePaths` 的 `-/run/xtables.lock`。锁文件在重启后可能尚不存在；不能依赖首次安装时临时 touch，也不能通过放开整个 `/run` 或取消沙箱修复。

## 验收与回退

- 使用实际域名和系统 CA 校验 HTTPS；匿名接口拒绝、CSRF、静态资源、源选择、真实计数与探测应逐项检查。真实链路验证需经过节点协议再访问 HTTPS 出口回显，不能只看 active 或端口监听。
- 计数先建立基线，完成真实业务请求后核对节点增量。面板重启不应重置核心或重复累计；缺失/过期速率不能显示成零流量或健康。
- 回退时恢复原 release、配置和必要单元，检查每一步结果；账本迁移和回退使用实际私有备份。Xray 账本与 sing-box 主账本独立，不能互相替代。
- 私有操作脚本、主机身份、原始配置/备份与验收数据应留在运维环境，不复制到公开 issue、日志、fixture 或 PR。
